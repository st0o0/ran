## Context

The `https` trap must reuse the HTTP request handling of `http-request-capture` and add TLS plus ClientHello fingerprints.

## Decisions

- **Shared handler.** `HTTPTrap` is built by `newHTTPTrap(proto, ...)`. `HTTPSTrap` embeds it and only sets a `wrap` hook that puts a TLS listener in front of the PROXY-aware listener. Sessions stay keyed by the accepted `net.Conn` (`ConnContext`/`ConnState`); `Stop(ctx)` is `http.Server.Close`, which also closes connections still in the handshake.
- **Handshake timeout.** `http.Server` handshakes `*tls.Conn` under `ReadTimeout`/`WriteTimeout`, which are the session timeout of `https`. A client that sends nothing is closed after that time.
- **Certificates.** One PEM file at `RAN_HTTPS_CERT_PATH` holding two certificate and PKCS#8 key pairs, ECDSA P-256 first and RSA-2048 second (`Certificates` order: `crypto/tls` serves the first one the ClientHello supports, so clients that only offer RSA suites get the RSA certificate). `CN=localhost`, 10 years. Missing, unreadable, invalid, incomplete (one algorithm missing), expired or not yet valid files are replaced; if the replacement cannot be written, ephemeral certificates are used and a warning is logged. The file is written atomically: temporary file in the same directory (mode `0600`), fsync, rename, so an existing file with looser permissions ends up `0600`.
- **Old clients.** The trap accepts them: `MinVersion` is TLS 1.0 and `CipherSuites` lists every suite `crypto/tls` implements (`tls.CipherSuites()` plus `tls.InsecureCipherSuites()`: RSA key exchange, 3DES, RC4, CBC-SHA256). An explicit `MinVersion` and `CipherSuites` override the defaults that the `GODEBUG` settings `tls10server`, `tlsrsakex` and `tls3des` control, so no `//go:debug` directive or `godebug` line is needed (tests handshake with real `crypto/tls` clients at TLS 1.0, 1.1, 1.2 and 1.3, ECDSA and RSA-only suites, 3DES included). TLS 1.3 suites are not configurable and always on. SSLv3 and SSLv2 are not implemented by `crypto/tls` and are impossible with the standard library; such hellos fail the handshake and are still fingerprinted.
- **ClientHello capture.** `tls.ClientHelloInfo` has no extension order and no raw GREASE-free extension list, so JA3/JA4 cannot be computed exactly from it. A small `helloConn` wrapper therefore records the first TLS record the client sends (at most 16389 bytes) and `parseClientHello` reads it. `GetConfigForClient` runs after the full hello was read and before version and cipher negotiation, so hellos that fail the handshake are fingerprinted too. The SNI comes from `ClientHelloInfo.ServerName` and falls back to the parsed one.
- **Bounds.** 256 cipher suites, 128 extensions, 64 groups, 16 point formats, 128 signature algorithms, 32 versions, 16 ALPN entries; SNI and ALPN pass through `sanitizeHTTPValue` (control characters replaced, 256 bytes). The parser is a bounds-checked cursor and never allocates from a length field.
- **JA3** follows the original definition (legacy version, ciphers, extensions, groups, point formats; GREASE removed; MD5). **JA4** is the TCP flavour (`t`). The version is the highest non-GREASE value of `supported_versions` when present (the legacy field is ignored then). If the first or last byte of the first ALPN value is not ASCII alphanumeric, the two ALPN characters are the first hex digit of the first byte and the last hex digit of the last byte, as in the JA4 specification (the FoxIO reference tools instead substitute `9` for non-ASCII bytes; the specification text is followed). GREASE is removed from ciphers, extensions and signature algorithms (confirmed by the FoxIO `sigalg-grease` capture). Ciphers and extensions (SNI and ALPN excluded) are sorted, signature algorithms stay in wire order, each hashed to 12 hex characters of SHA-256.

## Limitations

- Only a ClientHello that fits into the first TLS record is fingerprinted. A hello fragmented over several records is still handled by `crypto/tls` but gets no JA3/JA4 (SNI is still logged).
- Counts and lists are capped, so a hostile hello with more than the caps differs from the exact JA3/JA4 of the full hello.
- A failed handshake ends as a `probe` session with the default outcome; Go gives no per-connection handshake error to the trap, so no separate outcome label is set.
- SSLv3 and SSLv2 cannot be served with the Go standard library; those clients fail the handshake but are still fingerprinted.
- Fingerprint vectors: JA3 is checked against the example of the Salesforce ja3 README (a JA3 string and its MD5, so the hashing step, not a raw capture). JA4 is checked against two raw ClientHellos from the FoxIO ja4 repository captures (`tls12.pcap` exactly, `tls-non-ascii-alpn.pcapng` with the ALPN characters of the specification) and a synthetic rebuild of `sigalg-grease.pcapng`.
