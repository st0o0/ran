## Decisions

- **Modbus reads log, they do not alert.** Reads use `Session.Log` (action `probe`), so the counters stay zero and `Classify` returns `probe`. Writes and unknown codes use `LogPayload` plus an alert whose meta is the numeric request fields. FC 23 (read/write multiple registers) is a write.
- **Quantities are clamped, never used for sizing.** The PDU is already bounded by the MBAP length (at most 254 bytes). The declared quantity is only logged, cut to the specification maximum per function code.
- **ADB reads a bounded packet loop.** Up to 8 packets after the token, so the usual `AUTH signature` -> new token -> `AUTH public key` -> `OPEN` flow is captured. A signature is answered with a fresh token, a public key is not answered (adbd waits for the user). Only a SHA-256 is kept: `key_hash` for a public key, `signature_hash` for a signature (a hash of a per-token challenge answer is not a key identifier). A declared data length above 4096 ends the session instead of draining the rest, in the first CNXN packet as well, so leftover bytes are never parsed as packets. A plain EOF after the token is `completed`, not `error`.
- **Telnet IAC is parsed per line.** `parseTelnetIAC` works on the line returned by `readLineLimited`, so the 4096 byte bound stays. Replies are written before the next prompt, which means a client that sends options without a newline is answered late. `WILL` gets `DONT`, `DO` gets `WONT`; `DONT` and `WONT` need no answer, which also avoids negotiation loops. Replies are capped at 192 bytes per line. A subnegotiation that contains a newline is cut by the line reader: its unterminated start is dropped and the remainder, including a stray `IAC SE`, is the next line (nothing leaks into the field, no terminal type is logged). We never ask for the terminal type, so only clients that volunteer it appear in the log.
- **mysql retries use an authentication switch.** After a failed attempt (not the last) the trap sends `0xFE mysql_clear_password` and reads the next packet as a NUL terminated password. The user name stays the one from the handshake. Sequence numbers advance by two per round. The final answer is the same ERR 1045 as before. The switch is only sent to clients that set `CLIENT_PLUGIN_AUTH` in the handshake response; others get ERR 1045 at once (single attempt). A reply identical to the previous password is a repeat: ERR 1045 and end.
- **postgres re-asks the password.** A real server would send FATAL and close; no client continues after that, so intermediate rejections send nothing and the next `AuthenticationCleartextPassword` follows directly. The error response is sent after the last attempt. libpq and pgx answer a repeated request with the same stored password, so a password identical to the previous attempt is not counted, logged or reported and ends the session with the error response. In unlimited mode every iteration blocks on a client read or on the auth delay, and the session deadline ends it.
- **rdp stays single attempt.** The user name comes from the X.224 cookie of the connection request and the negotiation failure ends the exchange, so there is nothing to retry. The README says so instead of pretending.
- **Scan by ports.** `scanTracker.TouchPort` keeps `ports map[int]time.Time` per entry, expired on every touch and capped at 16 (above the threshold of 5, so a full live set already means scan). The tracker is only reached for TCP and non-ignored sources, so UDP and `RAN_IGNORE_IPS` stay out. Port 0 (unknown) is not counted. `Touch(ip, protocol)` remains for the protocol only callers.
- **authSleep honors the session deadline.** `Session.Deadline` is set where the connection deadline is set (tcp skeleton, ssh after the tarpit); `Session.authSleep` ends at it with `context.DeadlineExceeded` instead of overshooting by up to 3 delays. All callers (ssh, telnet, mssql, smb, mysql, postgres) use it; a zero deadline keeps the old behavior.
